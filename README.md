# @rapidd/build

Code generator that transforms Prisma schemas into Fastify CRUD APIs with TypeScript.

## Features

- **Automatic CRUD API Generation** - Creates Fastify routes from Prisma models (TypeScript)
- **Model Generation** - Creates TypeScript CRUD model classes
- **Access Control** - A starting `src/config/acl.ts`: an entry per model, credential columns hidden, the user table's password not writable through the API
- **Selective Generation** - Update only specific models or components

## Requirements

- **Prisma 7+**
- Node.js 22 or higher
- TypeScript 5.0+

## Installation

```bash
npm install @rapidd/build
```

## Quick Start

```bash
# Generate everything in current directory
npx rapidd build

# Generate in specific directory
npx rapidd build --output ./generated

# Generate only specific models
npx rapidd build --model user
npx rapidd build --model user,post

# Generate only specific component
npx rapidd build --only model
npx rapidd build --only route
npx rapidd build --only acl

# Combine model and component filters
npx rapidd build --model account --only route

# Code only — the Prisma client is up to date
npx rapidd build --skip-generate
```

## CLI Options

| Option | Description | Default |
|--------|-------------|---------|
| `-o, --output <path>` | Output directory | `./` |
| `-s, --schema <path>` | Prisma schema file | `./prisma/schema.prisma` |
| `-m, --model <names>` | Generate/update only these models, comma-separated | All models |
| `--only <component>` | Generate only: `model`, `route`, or `acl` | All components |
| `--skip-generate` | Do not run `prisma generate` first | Generate |

## Generated Code Examples

### Model

```typescript
// src/models/Users.ts
import { Model } from '../orm/Model';
import { QueryBuilder, prisma } from '../orm/QueryBuilder';
import type { ModelOptions } from '../types';

/**
 * getMany, get, create, update, upsert, upsertMany, count and delete are inherited from
 * Model. Override one to customize it for Users.
 */
export class Users extends Model {
    constructor(options?: ModelOptions) {
        super('users', options);
    }

    static override QueryBuilder = new QueryBuilder('users');
}

export { QueryBuilder, prisma };
```

### Route (Fastify)

```typescript
// routes/api/v1/users.ts
import { FastifyPluginAsync, FastifyRequest, FastifyReply } from 'fastify';
import { Users } from '../../../src/models/Users';

const usersRoutes: FastifyPluginAsync = async (fastify) => {
    fastify.addHook('preHandler', async (request, reply) => {
        if (!request.user) {
            return reply.sendError(401, 'no_valid_session');
        }
        request.model = new Users({ user: request.user, strictWrites: true });
    });

    fastify.get('/', async (request, reply) => { ... });
    // Ids go to the model as strings — it parses them by the key's type
    // (a non-numeric id for an Int key is a 400 invalid_id; composite keys: "a~b")
    fastify.get('/:id', async (request, reply) => { ... });
    // POST and PATCH respond with the record; ?include= adds relations, as on reads
    fastify.post('/', async (request, reply) => { ... });
    fastify.patch('/:id', async (request, reply) => { ... });
    fastify.delete('/:id', async (request, reply) => { ... });
};

export default usersRoutes;
```

Every model gets a route, addressed by its key: its `@id` / `@@id` — or, without one, its
`@unique` / `@@unique` (as `@rapidd/core` resolves it). A key of several fields is written
`a~b~c`, any number of them.

Junction tables (a two-field key whose fields are both foreign keys) become sub-routes of
their parents — `routes/api/v1/course/_student.ts` serves `/course/:id/student`. Each handler is
scoped to the parent in the URL: the list through `getMany({ where })` (a client `?q=` can only
narrow it), single records through the composite key. The parent's `index.ts` registers every
`_<name>` file next to it at startup, so a join table added to the schema later is served once
the build has written its sub-route. A parent route from an older build, or one generated as a
single file before it had join tables, is your code: the build prints the line to add to it.

> Sub-routes generated by 2.3.0 scoped the list with an object `q` that `@rapidd/core` ignored, so
> they listed every parent's rows. Updating `@rapidd/core` fixes them; regenerating (delete the
> `_*.ts` file, then `npx rapidd build --only route`) gives the current version.

> Routes generated before this version don't pass `?include=` on POST and PATCH. With
> `@rapidd/core` 3.0 their responses are the record alone; regenerate them (delete the file, then
> `npx rapidd build --only route`) to accept `?include=` on writes.

### Access control

`src/config/acl.ts` is written while it has no entry yet (the file `create-project` ships, or
none): an entry per model in which every user may create, read, update and delete, with
credential columns hidden from responses. The user table's password column is not writable
through the API either — it would be stored as sent, unhashed, and any user could set any
user's:

```typescript
// src/config/acl.ts
const acl: AclConfig = {
    model: {
        users: {
            canCreate: () => true,
            getAccessFilter: () => true,
            getUpdateFilter: () => true,
            getDeleteFilter: () => true,
            // Credential columns: never returned
            getOmitFields: () => ['password', 'reset_token'],
            // The sign-in password: not written through the API, which would store it unhashed and
            // let any user set any user's — set it in your own code with getAuth().hashPassword()
            getWritableFields: () => Object.keys(getFields('users')).filter((field) => field !== 'password'),
        },
        posts: {
            canCreate: () => true,
            getAccessFilter: () => true,
            getUpdateFilter: () => true,
            getDeleteFilter: () => true,
            // Credential columns: never returned (a required one stays writable)
            getOmitFields: () => ['api_key'],
        },
    },
};
```

The user table is the one `@rapidd/core` signs users in with: `DB_USER_TABLE`, else a model
called `user`, `users`, `account` or `accounts`. Its password column is `DB_USER_PASSWORD_FIELD`,
else one called `password`, `hash`, `passwd`, `pwd`, `password_hash`, `passwordhash` or
`hashed_password`. Both are read from the environment and the app's env file (`ENV_FILE`, else
`.env`). A user table without a password column — users sign in through LDAP, OIDC or WebDAV
only — gets no password rule.

Tighten each hook with your own logic — it receives the signed-in user, whatever your user table
or identity provider gives (Rapidd assumes nothing but `id`): `true` for all rows, `false` for
none, or a Prisma where such as `{ author_id: user.id }`. Once the file has entries it is your code
and is never changed again; models added later follow `ACL_DEFAULT` until you add theirs.

## Regeneration and existing files

- The generated entries hide credential columns (password hashes, secrets, tokens, API keys) from
  responses, and keep the user table's password out of what the API writes.
- Two models whose names give the same class (`user_role` and `UserRole`) stop the build — one
  model file would serve both tables. Rename one in the schema (`@@map` keeps its table).
- Models, routes, `src/config/user.ts` and an `src/config/acl.ts` with entries are never
  overwritten — they are your code.
- The Prisma client is regenerated first. The previous client is kept until `prisma generate`
  succeeds; if it fails, it is restored and the build stops with a non-zero exit code.
- The schema is read through Prisma's DMMF (`@prisma/internals`); a built-in parser is the
  fallback.

## Selective Generation

### Update Some Models

```bash
npx rapidd build --model account
npx rapidd build --model account,invoice
```

### Update Single Component

```bash
npx rapidd build --only route
npx rapidd build --only acl
npx rapidd build --only model
```

### Combine Filters

```bash
npx rapidd build --model user --only route
npx rapidd build --model account --only acl
```

## API Usage

```typescript
import { buildModels, parsePrismaSchema, generateAllModels } from '@rapidd/build';

// Full build
await buildModels({
  schema: './prisma/schema.prisma',
  output: './generated'
});

// Parse schema only
const { models, enums } = parsePrismaSchema('./prisma/schema.prisma');

// Generate models only
generateAllModels(models, './src/models');
```
